# 知识讲解口播：保留判断，铺设理解路径

用于从知识文档创作或修改整篇口播。若用户明确要求逐字朗读、文章导读、评论或其他体裁，按其选择调整；不要把本规则强加给所有内容。

## 先确定观众需要理解什么

默认观众没有读过原文。直接讲知识，让视频独立成立；不要用“这期借这篇文章”“作者接下来指出”代替解释。来源放入结构化引用和制作记录，需要归属或区分争议观点时可以自然署名。不得因此把他人的研究或观点说成自己的发现。

从原文识别贯穿全文的问题、关键专业判断、定义、公式、因果中介和限定。用户未固定时长时，按解释所需篇幅安排，不先套三分钟、十段或固定字数。省略次要内容时记录去向，不把核心洞察压成通用励志话。

## 全文采用有起伏的理解路径

对每个主要论证检查：观众为什么需要这个概念？怎样理解它？最后应该记住哪个精确判断？

一种常用安排是：**具体问题或案例 → 因果推演 → 专业判断 → 术语释义 → 现实含义**。按内容变换顺序；开场可以先立论，结尾可以收束，不要求每个镜头重复五步。一个论证也可以跨镜头完成。

- 保留原文有解释力的专业表述，尤其是定义、关键关系和结论。口语化主要用于铺垫、转折与释义；不要把“状态变量影响转移概率”一律磨成“过去会影响未来”。
- 案例讲出中间机制，再落到专业判断；出现难词后解释它在当前例子中具体指什么。准确概念帮助理解，名词数量不代表专业程度。
- 原句准确且适合听觉时原样保留。必要改写须保留变量、方向、条件、概率与因果强度。漂亮的原句若本身有歧义，先澄清，不为强调牺牲准确性。
- 原文引用、忠实改写、为理解新增的假设例子及建模类比分开记录。类比不是已证实的科学定律，引用也不是事实核验。
- 提问推动下一步推理，例子在后文回收；不要朗读章节目录、表格清单或剪辑指令，不要每段都用相同的“这就是”或金句腔。

例如，原文给出“状态变量会影响后续转移概率”时，可以先解释某次反馈如何改变练习行为，保留这句专业概括，再说明状态变量指积累的技能与习惯、转移概率指下一步更容易出现的状态。不能只剩一句“保持努力就会改变命运”，也不能把原句反复念几遍当作解释。这只是写法示例，不是所有主题都应采用的人生模型。

## 让强调进入交付，而不进入配音文本

在 visual-plan.md 按主要论证记录：原文锚点 → 铺垫所在句 → 专业判断所在句 → 释义或应用所在句。用 scene_id 与 narration 零基索引定位；跨镜头也要标明。以整篇为范围审查，不能只优化用户举出的那一句。

重点判断前后的停顿、关键词重音与解释段的平实语气写入制作记录；没有声音就不编秒数，不声称已听起来自然。narration 只保存实际要说的话，不包含“[停顿]”、加粗标记或朗读指令。

需要画面强调时使用现有 motion 的 text/stat.emphasis 或 formula.highlight，在 assets.screen_text 保存后期文字；有真实位图才登记 layers。定义说清后可切换到具体含义，完整关系图按讲解渐进展开；无需每句换画面。画面 emphasis 不是 TTS 重音参数，不保证声音效果。

修改口播后，从 storyboard 重新派生稿件，逐项检查 point_refs、assets、motion 和 layers 的语义对应。插入一句后仅索引仍在范围内，并不能证明旧触发仍对应正确内容。已有音频/cues 需重新录制或对齐，不沿用旧时间点。

## 审阅整篇，区分文件校验与内容判断

导出后用 narration-review.md 对照每幕的来源、真实口播与明确标记的画面重点；它是从当前 JSON 生成的审阅视图，不是独立编辑源，不是自动质量评分。无 motion 时也应审稿，不为了填满报告强行增加强调。

在 review.md 给每个主要论证记录具体观察，必要时引用句索引：

- 视频独立可理解，还是在假定观众读过原文？
- 专业判断及限定是否保留？是否被泛化口语稀释，或被夸大成必然结论？
- 铺垫、机制、术语解释与现实含义是否衔接？缺失时补解释，不用重复判断代替。
- 强调是否对应当前讲到的思想？口播与画面是否争抢信息、提前泄露复杂图或重复叠字？
- 段落节奏是否有变化？文字可读、录音自然、画面可读、时间同步应分别验收；未观察的项目写 unverified。

没有自动规则能仅靠关键词数、加粗数或公式数认定“专业、忠实、讲清楚”。CLI 通过只说明结构和文件有效。
